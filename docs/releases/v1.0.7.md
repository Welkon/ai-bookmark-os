# AI Bookmark OS v1.0.7

本版本聚焦 AI 分类的容错能力、导入数据的安全校验，以及后台请求与界面的健壮性，确保部分失败时仍保留可用结果、异常数据不再写入本地存储、渲染异常不再导致白屏。

## AI 分类容错

- 分类结果解析兼容模型返回的数字与数字字符串索引（部分 Anthropic 协议响应会以字符串形式返回类别序号），无效索引安全跳过。
- 标签阶段仅在整批零结果时才判定失败；个别书签缺失会回退为空标签且不写入缓存，不再因单条异常中断整批任务。
- 分配阶段对缺失书签统一回退到“其他”目录，并保证兜底目录始终存在，避免书签在失败后丢失归属。
- 局部范围分类改用祖先路径拼接，生成与全量扫描一致的绝对路径，防止“保留目录”因路径不匹配而被误重分类。

## 导入与数据安全

- 导入配置时保留本地的 `baseUrl`、`customFullUrl`、`customApiStyle`，防止被篡改的导入包将真实 API Key 指向任意外部端点。
- 新增配置校验：`baseUrl` 必须为 https（`localhost`/`127.0.0.1` 例外），并校验 `customApiStyle` 枚举、`customFullUrl` 类型、`classifyPrompts` 与保留目录字段的结构。
- 强化已保存分类结果与目录树的递归校验，拒绝形如 `[null, {name:123}]` 的畸形数据；时间戳改用有限数值判定，避免 `NaN` 蒙混通过。
- Gemini 的 Base URL 为空时回退到服务商默认地址，测试连接与模型列表均适用。

## 后台与请求健壮性

- 抓取正文统一截断到 8000 字符，避免超大内容触及 `chrome.storage.local` 配额上限。
- 仅对真正发起抓取的操作要求安全外链，删除、编辑等操作不再被 `file://`、`chrome://` 等地址阻断。
- 快速收藏的待处理项增加 5 分钟有效期并在创建失败时清理，避免陈旧状态堆积。
- 清空全部书签由串行改为并发（上限 10），并为 RSS 相关异步处理补齐失败回调，避免请求悬挂。

## 界面体验

- 新增 React 错误边界：侧边栏渲染异常时展示错误信息与重新加载入口，不再白屏。
- 对缺失的摘要、标签字段做字段级可选链处理；Service Worker 首条消息被拒时改为重试调度，而非直接报告失败。
- 确认面板新增失败态提示（中英双语），引导用户重试或关闭。

## 智能标签

- 移除失效的死代码分支，域名后缀改为严格后缀匹配（避免 `notgithub.com` 命中 `github.com`）。
- 引入文档频率（IDF）与负分阈值处理，保留多信号权重，提升标签相关性。

## 验证

- `npm test`：46 个测试文件全部通过，新增标签与分配阶段的容错回退回归覆盖。
- `npm run typecheck`：通过。
- `npm run build`、`npm run preview:check`：通过。

## 安装

下载 `ai-bookmark-os-v1.0.7-chrome-extension.zip`，完整解压后，在 Chrome 的 `chrome://extensions` 页面开启开发者模式，选择解压后直接包含 `manifest.json` 的目录加载。
